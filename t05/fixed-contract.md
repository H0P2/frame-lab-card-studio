# T05 고정 계약 — 템플릿 JSON 가져오기 확인 단계

고정 시점: 2026-10-08 (KST), AI A 구현 시작 전. 원본 GitHub 버전: `3d4032fefd88b901605f248bdb8f98e09e1e49d2`.

## 목표와 공통 제한

과제 3 Frame Lab에서 JSON 파일 선택 시 모든 항목을 검증하고 신규 ID 수와 기존 ID 갱신 수를 보여준다. 사용자가 **적용**하기 전에는 IndexedDB를 변경하지 않는다. **취소**는 저장된 템플릿을 그대로 둔다. 기존 JSON 형식(`frame-lab-templates`, 버전 1), 24개와 32MB 한도는 유지한다.

- AI A: Codex. AI B: 다른 서비스 또는 모델. B에게는 저장소와 A의 일곱 항목 인수인계만 준다.
- 각 AI의 실제 작업시간 상한: 45분. 각 AI에게 보내는 명시적 작업 요청 상한: 4회. 자동 도구 호출 횟수는 별도 기록한다.
- 두 AI에 같은 최초 요청: “Frame Lab의 템플릿 JSON 가져오기에 검증 결과 미리보기와 명시적 적용·취소를 추가하세요. 아래 I01–I10을 바꾸지 말고 실행 결과를 기록하세요. 원본 형식과 기존 편집 기능을 유지하세요.”
- 검사 삭제, 완화, 기대값 변경은 0건으로 고정한다. 결과는 PASS/FAIL/미실행으로 기록한다.

## 고정 검사 10개

모든 입력의 `editor`는 현재 `exportJSON()`이 만든 정상 설정을 사용한다. 각 검사는 `?lab`의 격리된 IndexedDB에서 독립 실행하고, DB 전후 레코드의 ID·이름·수·내용을 비교한다. `existing-0001` 등의 ID는 형식에 맞는 합성값이다.

| ID | 입력 | 관찰 가능한 기대값 |
|---|---|---|
| I01 | 비어 있는 DB에 신규 ID `incoming-0001` 한 건이 담긴 정상 JSON을 선택 | 확인 화면에 `신규 1 · 갱신 0`; 적용 전 DB 0건 |
| I02 | I01 확인 화면에서 취소 | 확인 화면이 닫히고 DB 0건, 템플릿 목록 0건 |
| I03 | I01 정상 JSON을 다시 선택해 적용 | DB와 목록에 `incoming-0001` 1건; 완료 메시지에 신규 1 · 갱신 0 |
| I04 | DB에 `existing-0001`이 있을 때 같은 ID의 새 이름과 신규 `incoming-0002`를 함께 선택 | 확인 화면에 `신규 1 · 갱신 1`; 적용 전 기존 이름과 DB 1건 유지 |
| I05 | I04에서 적용 | `existing-0001` 이름 갱신, `incoming-0002` 추가, DB와 목록 총 2건 |
| I06 | 손상된 JSON 문법 파일 선택 | 오류 표시; 확인 화면 없음; DB와 목록 변화 0건 |
| I07 | 한 파일에 중복 ID 두 건 선택 | 전체 거부; 확인 화면 없음; DB 변화 0건 |
| I08 | 두 항목 중 두 번째 `editor.ratio`가 허용되지 않은 값인 파일 선택 | 전체 거부; 첫 항목도 DB에 저장되지 않음 |
| I09 | 기존 24건 상태에서 신규 ID 한 건 선택 | 24개 한도 오류; 확인 화면 없음; DB 24건 그대로 |
| I10 | 파일 선택 후 적용 전에 다른 파일을 다시 선택 | 마지막 파일의 신규·갱신 수만 표시; 앞 파일의 항목은 적용 후에도 저장되지 않음 |

## 측정·제출 규칙

- 오류 수는 I01–I10 중 하나 이상 FAIL인 **전체 실행 회차 수**이다. 미실행은 FAIL로 꾸미지 않고 별도 표시한다.
- A 시작·종료, B 시작·종료의 실제 KST 시각과 40자리 소스 버전을 기록한다.
- A 인수인계는 목표 / 현재 상태 / 실행 명령 / 통과 검사 / 남은 문제 / 다음 행동 / 건드리지 말 것의 7항목이다.
- 비교표의 판정 구간에서는 모델·서비스 이름을 가리고, 실측 시간·요청 수·오류 회차·통과 수를 적는다. 학생 본인 판단은 학생 피드백 전에는 비워 둔다.
