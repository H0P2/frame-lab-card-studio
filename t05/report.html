Frame Lab의 템플릿 JSON 가져오기를 두 AI 단계로 완성했다. 첫 단계는 검증과 미리보기에서 멈추고, 다음 단계는 대화 전문 없이 공개 저장소와 7칸 인수인계만 받아 원자적 적용을 완성했다.

완성된 동작

JSON 파일을 선택하면 전체 항목을 먼저 검증하고 신규 N · 갱신 M을 보여준다. 적용 전에는 브라우저 저장소를 바꾸지 않는다. 취소하면 현재 목록이 유지된다. 적용을 누르면 그 시점의 저장소 상태에서 24개·32MB 한도를 다시 확인하고 한 번의 트랜잭션으로 반영한다.

이름을 가린 비교

판정 표에서는 서비스와 모델 이름을 표시하지 않았다. 시간은 각 단계의 실제 시작부터 중단·완료까지, 오류는 고정 검사 10개를 모두 실행한 회차에서 FAIL이 하나라도 나온 횟수다. 답변의 코드 문제만 발견한 검토는 오류 회차에 넣지 않았다.

짧은 확인 방법 · 4줄

① 위치Frame Lab 공개 편집기의 ‘내 템플릿 → 옮겨 쓰기’로 이동한다.
② 행동검사용 JSON을 저장해 가져온 뒤 미리보기의 개수를 확인하고 ‘적용’을 누른다. 취소 동작도 같은 파일로 확인할 수 있다.
③ 통과 모습적용 전 ‘신규 1 · 갱신 0’이 보이고 목록은 그대로다. 적용 뒤 새 템플릿 1개와 완료 문구가 보인다.
④ 안 될 때손상된 JSON이나 24개 한도 초과는 오류를 표시하고 기존 목록을 유지한다. 저장소 연결이 없으면 적용 버튼을 사용할 수 없다.

AI와 내 판단 · 3줄

AI에게 맡긴 일첫 세션에 전체 검증·미리보기·취소를, 새 세션에 저장 직전 재검증과 원자적 적용 코드를 맡겼다.
직접 판단한 일같은 10개 검사를 먼저 고정하고, 실제 브라우저 결과와 저장소 코드를 기준으로 인수인계 및 완료 여부를 판정했다.
따르지 않은 일새 세션의 초기 일반 예시는 존재하지 않는 함수와 다른 DB 이름을 사용해 적용하지 않았다. 두 번째 안의 오래된 목록 기준 32MB 검사도 채택하지 않고, 현재 DB 기준으로 고쳤다.

다음 작업의 도구 선택 기준

소스 수정과 실제 검사가 필요하면 저장소를 직접 다룰 수 있는 도구를 먼저 쓰고, 대화 단절을 시험할 때는 다른 서비스에 고정 소스와 인수인계만 전달하며, 독립 검토 결과는 비교 판정과 분리한다.

비교 후 독립 검토

무료 Claude를 세 번째 검토자로 사용했다. Claude는 코드를 읽고 미리보기 이후 DB 변경, 영상 저장 중 적용, 적용 버튼 중복 클릭을 지적했다. 운영자가 이를 수정하고 브라우저에서 고정 검사 10/10, 별도 동시성 검사 3/3, 기존 기능 재검사 52/52를 확인했다. Claude가 검사를 직접 실행한 것은 아니다.

기존 기능 재검사 도구의 첫 실행은 이전 ‘파일 선택 즉시 저장’ 절차를 기대해 실패했다. 새 ‘미리보기→적용’ 동작에 맞게 검사 행동만 바꾸고 기대값은 유지한 뒤 52개를 모두 통과했다. 이 후속 검토와 수정은 위 세션 α/β의 비교 수치에 포함하지 않았다.
