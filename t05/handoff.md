# T05 · AI A → AI B 인수인계

AI B에게는 이 문서와 공개 저장소만 제공한다. AI A의 대화 내용은 제공하지 않는다.

## 1. 목표

Frame Lab 템플릿 JSON을 선택하면 전체 검증 후 `신규 N · 갱신 M`을 보여주고, 명시적 적용 전에는 IndexedDB를 변경하지 않도록 완성한다. 취소는 저장소를 유지한다. 고정 검사 `t05/fixed-contract.md`의 I01–I10을 바꾸지 않는다.

## 2. 현재 상태

- 원본 공개 소스: `H0P2/frame-lab-card-studio@3d4032fefd88b901605f248bdb8f98e09e1e49d2`.
- AI A 중단 소스 버전: `1f9d533371b462225e65bf103fc7090a6a30f735` (원본 공개 저장소의 커밋 이력 위에서 생성).
- `app.js`에서 파일 전체 검증과 이미지 정리, 신규·갱신 수 계산을 한 뒤 `pendingImport`에 보관한다. `index.html`에 확인 영역과 취소 버튼을 추가했다.
- 적용 버튼은 계획적으로 비활성화해 두었다. **AI B가 완성할 기능은 한 개: 검증된 항목의 원자적 적용**이다.

## 3. 실행 명령

Node.js가 설치된 새 작업 폴더에서 저장소를 받은 뒤, 저장소 루트에서 `node t05/serve.mjs`를 실행한다. `http://127.0.0.1:8883/t05/checks.html`을 열어 `10개 검사 실행`을 누른다. `http://127.0.0.1:8883/index.html?lab`은 격리된 수동 검사 화면이다. 포트 8883이 이미 쓰이면 기존 서버를 종료한 뒤 실행한다. 별도 패키지 설치는 없다.

## 4. 통과 검사

실제 브라우저 전체 검사 1회: PASS I01, I02, I04, I06, I07, I08, I09 (7/10). 원본은 `t05/a-results.json`이다. 오류 회차는 1회이며, FAIL 3개는 I03, I05, I10이다. 실패 사유는 모두 적용 버튼 비활성이다.

## 5. 남은 문제

`pendingImport.records`를 적용하는 코드가 없고 적용 버튼이 비활성화되어 있다. 적용 직전 DB의 현재 레코드와 24개·32MB 한도를 다시 확인하고, 하나의 `readwrite` 트랜잭션에서 모두 저장해야 한다. 성공 후 목록 갱신과 `신규 N · 갱신 M` 완료 메시지를 표시한다. 실패 시 확인 상태와 DB가 일관돼야 한다.

## 6. 다음 행동

`app.js`의 `previewImportJSON`, `cancelImportJSON`, `dbWrite`, `bind`, `syncStorageControls`를 확인한다. `applyImportJSON`을 만들고 적용 버튼을 연결한다. 저장소 연결이 끊겼을 때는 적용을 막는다. 같은 I01–I10을 재실행해 실제 결과를 `t05/b-results.json`에 기록한다. 검사 하나라도 실패한 전체 실행 회차를 오류 1회로 센다.

## 7. 건드리지 말 것

고정 검사 10개의 ID·입력·기대값, AI별 45분/명시적 요청 4회 상한, 기존 JSON 형식·버전, 템플릿 24개·JSON 32MB 한도, 개인정보·비밀값 제거 원칙을 바꾸지 않는다. AI A 대화 전문을 B에게 제공하지 않는다. 기존 과제 3 검사 기록을 새 검사 결과로 덮어쓰지 않는다.
